A little history of unix and “commodity” computing

  • We take for granted the notion that we can “start the computer” and “type in commands” and get essentially immediate responses for many tasks
  • The origins of this capability are historically complex; let’s have a little background

Antitrust (facts from sonnet and gemini)

  • True or false: Because of AT&T’s 1956 antitrust consent decree, the company was barred from competing in the computer business, so it could not sell Unix as a commercial product. Instead it licensed the source tape to universities for a nominal fee (little more than the cost of media and shipping).

  • True: To resolve an antitrust lawsuit (United States v. Western Electric Co.), AT&T signed a consent decree restricting the Bell System to regulated “common-carrier telecommunications services” and related equipment manufacturing. The decree legally barred AT&T from entering other commercial markets, including data processing and computer software.

“Shipping costs”

  • Licensing Unix “As-Is”: Because AT&T could not market Unix as a commercial software product, Bell Labs provided the source code to universities, research labs, and government agencies under an educational license. The fee was nominal—typically around $150 to $300—just enough to cover magnetic tapes, printed documentation, and handling. AT&T explicitly provided no technical support, warranty, or bug fixes.
  • The Impact: This policy inadvertently sparked a computing revolution. Because universities received full source code and had to maintain the OS themselves, a generation of students and researchers studied, debugged, and extended Unix. This culture gave rise to John Lions’ famous Commentary on UNIX 6th Edition, the Berkeley Software Distribution (BSD), and the modern open-source movement. When AT&T was broken up in 1984 and released from the 1956 decree, the company immediately sought to commercialize Unix (System V) and enforce strict, expensive licensing, igniting the famous “Unix Wars.”

Naming conventions for file collections

  • Name your files in a way that is related to their contents and specifies how they relate to other files.

  • The Smithsonian Data Management Best Practices has “Five precepts of file naming and organization”

  • Any folder worth creating deserves a README.md inside the folder explaining why it was made and what its intended contents are —

Five precepts of file naming and organization

  • Have a distinctive name that describes the content.
  • Follow a consistent pattern that fosters convenient references to files to simplify software that operates on them
  • Organize files into directories that follow a consistent pattern.
  • Avoid repetition of semantic elements among file and directory names.
    • What could that mean?
  • Have a file extension that matches the file format (no changing extensions!)
    • jpg and jpeg are suffixes for a fixed image format
    • sometimes csv is used as a suffix for tsv information! and vice versa
    • .txt conveys very little information
  • markdown and json are formats that you should be comfortable with

For specific recommendations we recommend you follow The Tidyverse Style Guide

The System

  • Instead of clicking, dragging, and dropping to organize our files and folders, we will be typing Unix commands into the terminal.

  • The way we do this is similar to how we type commands into the R console, but instead of generating plots and statistical summaries, we will be organizing files on our system.

  • The file system is hierarchical, you create directories (folders) in other folders

  • When you log in to a Unix computer you are in your home directory

  • the command line has a prompt that is configurable and is printed on screen to let you know that the terminal is ready for input

  • Environment variables control your computing environment and many are customizable by users

  • LLMs are useful tools for finding commands and getting help navigating through your first exposure to Unix and the ideas it is based on

The terminal

  • The terminal is integrated into Mac and Linux systems, but Windows users will have to install an emulator.

  • Once you have a terminal open, you can start typing commands.

  • You should see a blinking cursor at the spot where what you type will show up. This position is called the command line.

The filesystem

Files and permissions

  • within each directory you can create files and other directories

  • files whose names start with a period . are hidden by default; use ls -a to view them

  • files have permissions: use ls -lh to view details

drwxr-xr-x    4 robert  staff   128B Aug  8 10:03 bin
-rw-r--r--@   1 robert  staff    20M Jun 24 09:11 boots.png
-rw-r--r--@   1 robert  staff    26M Jun 23 15:23 boots1.pdf
  • you can read, write, or execute files and control who can see or use them by changing permissions

Working directory

  • The working directory is the directly you are currently in.

  • Commands you issue will generally take effect in this directory

  • You can see your working directory using the Unix command pwd

  • You can list the contents of the directory (files and other directories) using ls

  • You can find out about how ls works by issuing the command: man ls

Paths

  • The string returned by pwd command is the full path to the working directory.

  • The full path to your home directory is stored in an environment variable.

  • You can see it like this echo $HOME

Paths

  • In Unix, we use the shorthand ~ as a nickname for your home directory

    • Example: the full path for docs (image in prev. slides) can be written like this ~/docs.

  • A common default for the prompt is to show the path to the working directory (that path might be long, but you can change it)

  • Let’s open a terminal window and see what the prompt is.

  • you have an environment variable called PATH which you can display using echo

    • that variable is a set of individual paths, separated by : (colon) and it tells your Unix shell where to look for commands

    • you can modify that path, so that you can have it look for commands in other, non-standard places (eg make your own bin directory)

Unix commands

  • ls: Listing directory content

  • mkdir and rmdir: make and remove a directory

  • cd: navigating the filesystem by changing directories

  • pwd: see your workding directory

  • mv: moving files

  • cp: copying files

  • rm: removing files

  • more and less: display the contents of a file

Autocomplete

  • In Unix you can auto-complete by hitting tab.

  • This means that we can type cd d then hit tab.

  • Unix will either auto-complete if docs is the only directory/file starting with d or show you the options.

  • Try it out! Using Unix without auto-complete will make it unbearable.

Other useful commands

  • curl - download data from the internet.

  • tar - archive files and directories into one file.

  • gzip, zstd - and other compression tools - make big files small

  • ssh - connect to another computer.

  • find - search for files by filename in your system.

  • grep - search for patterns in a file.

  • awk/sed - These are two very powerful commands that permit you to find specific strings in files and change them.

  • many software tools use hidden files and directories to provide customization e.g. .gitconfig or .ssh
